# 현지 대리인 선정·운영 프레임워크: 선임 요건부터 위임·교체까지

해외 상표를 처음 진행하는 팀은 대리인 문제를 "어디가 좋은지 고르는 일"로 접근합니다. 그런데 실제로 일정이 밀리는 지점은 후보 비교가 아니라 그 앞단입니다. 어느 관할에서 대리가 법적으로 필요한지, 어디는 주소만 있으면 되는지, 어느 단계부터 요건이 발동하는지를 구분하지 못한 채 움직이면 후보를 아무리 잘 골라도 순서가 어긋납니다.

전형적인 장면은 이렇습니다. 여러 나라에 동시에 출원하기로 하고 한 곳에 통합 위임을 맡겼는데, 미국은 자격 요건이 따로 있고, 영국은 대리인이 아니라 송달주소 문제였고, 마드리드로 낸 건은 거절통지가 오기 전까지는 현지 대리인을 지정할 자리조차 없었습니다. 여기에 계정과 연락처가 대리인 쪽에 몰려 있으면, 나중에 담당자나 대리인을 바꿀 때 기록을 되찾는 일이 다시 과제가 됩니다.

이 리포트는 관할별 요건을 네 가지로 나눠 보고, 그다음에 후보 평가·위임 범위·정기 점검·교체까지 하나의 운영 흐름으로 잇습니다. 특정 대리인을 추천하거나 비용을 비교하지 않습니다. 로펌을 붙이기 전에 내부에서 먼저 끝내야 하는 판단을 정리하는 것이 목적입니다.

### 지금 이 리포트를 먼저 보면 좋은 이유

대리인 이야기는 7개 가이드 어디에나 조금씩 나오지만, 한곳에 모여 있지는 않습니다. 각 가이드는 자기 관할의 실행 순서 안에서 대리인을 다루기 때문에, 여러 나라를 동시에 움직이는 팀은 같은 질문을 관할마다 처음부터 다시 하게 됩니다.

| 현재 가이드가 이미 잠근 것 | 이 리포트가 회수하는 공통 질문 |
|---|---|
| ChaTm: 대리인 전달 전 red-line 검토와 handoff 메모 | 관할이 달라도 같은 handoff 패킷 구조를 쓸 수 있는가 |
| MexTm: 위임장·서명 권한과 대리 실무 | 위임 범위와 서명 권한을 어느 선까지 내부에 남길 것인가 |
| EuTm: 대표자/대리인 handoff 규칙과 control sheet | 대리 의무와 송달주소 요건을 어떻게 구분해 관리할 것인가 |
| UsaTm: 외부 변호사를 포함한 운영 체계 설계 | 자격 요건이 있는 관할에서 선임 구조를 언제 잠글 것인가 |
| UKTm·LatTm: 외부 대리인 인터페이스와 관리 체계 | 여러 대리인을 동시에 운영할 때 무엇을 표준화할 것인가 |

즉 이 문서는 guide를 대체하는 자료가 아니라, 각 guide가 이미 잠근 실행 질문을 교차 관할 운영 구조로 다시 엮는 trust layer입니다.

### 먼저 네 가지 요건을 구분한다

가장 큰 실수는 "현지 주소가 필요하다"를 "현지 대리인을 반드시 선임해야 한다"로 읽는 것입니다. 이 둘은 관할과 절차에 따라 성립하지 않을 수 있습니다. 아래 네 가지를 처음부터 다른 칸에 적어야 뒤에서 순서가 꼬이지 않습니다.

| 유형 | 의미 | 판단이 필요한 것 |
|---|---|---|
| 법정 대리 의무 | 특정 자격을 갖춘 변호사·변리사·상표대리기구를 선임해야 함 | 요구되는 자격이 무엇인지, 언제부터 적용되는지 |
| 송달주소·연락점 의무 | 관할 내 주소가 필요하지만, 그 자체가 전문대리인 선임 의무는 아님 | 어떤 주소가 유효한지, 누구 명의로 둘지 |
| 단계별 의무·예외 | 출원 행위 자체는 예외지만 후속 절차부터 의무가 생기는 경우 | 어느 시점에 요건이 발동하는지 |
| 운영상 협업 권고 | 법적으로는 선택이나 언어·기한·현지 계정·보정 대응 때문에 실무 가치가 큰 경우 | 내부 역량으로 감당 가능한 범위인지 |

네 번째 유형을 "사실상 필수"라고 부르지 않는 편이 좋습니다. 그렇게 적으면 법정 의무와 같은 무게로 읽히고, 정작 진짜 의무가 있는 관할에서 긴장이 풀립니다.

### 관할·경로별 대리 및 송달 요건 지도

아래 표에서 Madrid는 관할이 아니라 **경로**입니다. 국제단계의 규칙과 지정국의 규칙이 다른 층에서 작동하므로 같은 칸에 넣지 않습니다. 표의 각 행은 공식 기관 자료를 기준으로 정리했고, 근거가 충분히 확인되지 않은 항목은 의무로 적지 않았습니다.

| 관할/경로 | 유형 | 확인된 내용 |
|---|---|---|
| 미국 | 법정 대리 의무 | 미국 외에 domicile을 둔 출원인·등록권자·TTAB 당사자는 USPTO 앞에서 자격을 갖춘 미국 면허 변호사의 대리를 받아야 합니다. domicile 주소 제출은 모든 출원인에게 적용되는 별개 요건입니다. |
| EU | 법정 대리 의무 + 단계 예외 | EEA 안에 domicile, 주된 영업소 또는 실질적·실효적 영업소가 없는 당사자는 EUIPO 절차에서 대리인을 선임해야 합니다. 다만 **EU 상표 출원 행위 자체는 제외**됩니다. |
| 영국 | 송달주소 의무 | 영국·지브롤터·채널제도의 송달주소가 필요합니다. Isle of Man도 유효 주소로 인정됩니다. 대리인을 두는 경우 그 대리인이 해당 지역 주소를 가져야 한다는 형태이지, 전문대리인 선임 자체를 의무화하는 요건과는 다릅니다. |
| 중국 | 법정 대리 의무 | 중국 내 상거소나 영업소가 없는 외국인·외국기업은 자격을 갖춘 상표대리기구에 위임해야 합니다. 중국 내 상거소가 있는 외국인은 직접 출원할 수 있습니다. |
| 일본 | 법정 대리 의무 | 일본에 주소·거소(법인은 영업소)가 없는 재외자는 일본에 주소·거소를 둔 상표관리인을 통해 절차를 밟습니다. 재외자가 대리권 범위를 제한하면 그 범위에 따릅니다. |
| 멕시코 | 송달주소 의무 | 멕시코 국내에 통지를 받을 주소와 이메일 주소를 기재해야 하고, 변경 시 통지해야 합니다. 전문대리인 선임이 법정 의무인지는 이번 정리에서 공식 근거로 확인하지 못했으므로 의무로 적지 않습니다. |
| Madrid (경로) | 단계별 조건 | 국제단계의 대표자 선임은 선택입니다. 다만 거절통지에는 그 절차에서 현지 대리인이 필요한지가 함께 안내되며, 필요 여부는 지정국 규칙에 따릅니다. |

#### 이 표에서 자주 어긋나는 지점

- **자격의 정확한 표현.** 미국에서 요구되는 것은 "미국 현지 대리인"이 아니라 USPTO 앞 실무 자격을 갖춘 미국 면허 변호사입니다. 브리프에 "현지 대리인"이라고만 적으면 후보 검토 단계에서 자격 확인이 빠집니다.
- **중국의 자회사·대표처 구분.** 법에 따라 설립된 외국기업의 중국 내 완전자회사는 중국기업으로 보지만, 외국회사가 세운 중국 내 사무소나 대표처는 그 외국회사의 중국 내 영업소로 보지 않습니다. 여기서 판단이 갈립니다.
- **EU의 기준선.** "EU 밖"이 아니라 EEA 기준이고, 예외도 "출원 절차 전체"가 아니라 출원 행위 자체로 좁게 읽어야 합니다. EEA 밖 법인이라도 경제적 연결이 있는 다른 법인의 EEA 소재 피용자를 통해 행위할 수 있는 길이 있습니다.
- **Madrid의 시차.** 국제출원에는 지정국 대리인을 지정하는 자리가 없습니다. 미국을 지정한 경우 실제 선임이 필요해지는 시점은 거절통지가 나온 때부터입니다. 이 시차를 모르면 "왜 아직 대리인이 없느냐"는 내부 질문이 반복됩니다.

관할별 요건은 개정될 수 있습니다. 위 내용은 공개용 정리이며, 실제 위임 전에는 각 기관의 공식 안내와 현지 전문가로 다시 확인하는 편이 안전합니다.

### 내부 결정과 외부 대리인의 경계를 잠근다

출원 품질은 대리인이 뛰어나서만 좋아지지 않습니다. 내부에서 무엇을 확정해 넘기느냐가 더 크게 작용합니다. 내부 결정이 안 끝난 상태로 넘기면 대리인이 아무리 빨라도 보정과 재작업이 반복됩니다.

| 항목 | 내부에서 확정 | 대리인과 함께 | 대리인 판단 영역 |
|---|---|---|---|
| 표장 버전 | ● | | |
| 출원인 명의·권리자 구조 | ● | | |
| 지정상품·서비스 범위 | ● | ● | |
| 관할별 문구 적합성 | | ● | ● |
| 출원 경로 선택 | ● | ● | |
| 거절 대응 방향 | ● | ● | |
| 제출 문안 확정 | | ● | ● |
| 사업상 양보 가능 범위 | ● | | |

핵심은 사업 판단과 절차 판단을 섞지 않는 것입니다. 대리인 의견을 그대로 사업 우선순위로 받아들이면 대응 방향은 정리돼도 사업 결정이 뒤로 밀립니다.

### 후보 평가 5축

후보 비교는 항목을 늘릴수록 좋아지지 않습니다. 아래 다섯 축 정도면 대부분의 선택이 갈립니다.

| 축 | 무엇을 보는가 | 확인 방법 |
|---|---|---|
| 관할 실무 적합성 | 우리 업종·권리 유형에서 실제로 다뤄 본 절차 범위 | 유사 절차 유형별 처리 경험, 우리가 예상하는 이슈에 대한 설명 방식 |
| 커뮤니케이션과 응답 | 기한 관리와 회신 속도가 조직 리듬에 맞는가 | 표준 회신 기한, 담당자 부재 시 백업, 사용 언어와 보고 형식 |
| 이해상충 | 검색 범위와 통지 절차가 정해져 있는가 | 아래 별도 항목 |
| 기록과 반환 | 종료 시 무엇을 어떤 형태로 돌려받는가 | 아래 위임 범위 항목 |
| 비용 구조의 투명성 | 금액이 아니라 구조가 설명되는가 | 아래 비용 항목 |

#### 선정 전 브리프 질문지

질문은 "좋은 답"을 받아내려고 던지는 것이 아닙니다. 답변이 **확인 가능한 형태**로 오는지를 보는 것입니다.

| 질문 | 확인 가능한 답변 신호 | 추가 확인이 필요한 신호 |
|---|---|---|
| 이 관할에서 우리 유형의 절차를 어떤 범위까지 다루는가 | 절차 유형과 단계를 나눠 설명 | 전반적으로 가능하다는 포괄적 답변 |
| 표준 회신 기한과 담당자 부재 시 처리는 | 기한과 백업 담당이 문서로 제시됨 | 사안별로 다르다는 답만 돌아옴 |
| 이해상충 검색 범위는 어디까지인가 | 검색 대상 조직 범위를 특정 | 문제없다는 결론만 제시 |
| 비용은 어떤 단위로 산정되는가 | 단계별 scope와 포함·별도 업무 구분 | 총액만 제시 |
| 계약 종료 시 자료 반환은 | 반환 형식과 기간을 명시 | 요청 시 협의라고만 답변 |
| 기한 관리와 통지는 어떤 방식인가 | 통지 시점과 채널이 정해져 있음 | 통지 시점 언급 없음 |

답변 자체가 결과를 보장하지는 않습니다. 다만 확인 가능한 형태로 답이 오는지는 이후 운영 난이도를 꽤 정확하게 예고합니다.

#### 이해상충은 범위를 묻는다

체크박스로 "충돌 없음"을 받는 것으로는 부족합니다. 최소한 아래는 범위를 특정해 두는 편이 좋습니다.

- 검색 대상이 조직 전체인지, 담당팀 범위인지
- 계열사와 현지 제휴사까지 포함하는지
- 상대방 또는 주요 유통사와의 기존 업무가 있는지
- 새로 충돌이 생겼을 때 통지 절차와 시점이 정해져 있는지
- waiver를 요구받을 경우 내부에서 누가 승인하는지

#### 비용은 금액이 아니라 구조로 본다

관할마다 허용되는 보수 구조가 다르므로, 특정 산정 방식을 공통 선택지로 전제하지 않는 편이 안전합니다. 대신 아래가 분리돼 설명되는지를 봅니다.

- 관납료와 전문서비스 비용의 분리
- 출원·보정·이의·갱신·분쟁 등 단계별 scope 분리
- 기본 범위에 포함된 업무와 별도 청구 업무의 구분
- 번역·공증·송달·제3자 비용의 처리 방식
- 해당 관할의 직업윤리·법령상 허용되는 보수 구조인지 여부

### 위임 범위·계정·연락처의 소유권을 설계한다

여기서 정리를 미루면 나중에 대리인을 바꿀 때 비용이 커집니다. 다만 "포털 계정을 절대 넘기지 않는다"는 식의 단정은 현실과 맞지 않습니다. 일부 관할의 제출 시스템은 자격자 계정 사용을 전제로 하기 때문입니다. 그래서 소유권을 층으로 나눠 설계합니다.

| 대상 | 원칙 |
|---|---|
| 회사 도메인·대표 이메일·브랜드 계정 | 회사 소유로 유지 |
| 회사가 직접 개설 가능한 관청·플랫폼 계정 | 회사 명의로 개설하고 접근 권한만 부여 |
| 자격자 전용 제출 계정 | 대리인이 운영하되, 사건 데이터 접근·export·반환 권리를 계약에 명시 |
| 공식 송달 연락처 | 요건에 맞게 지정하되 내부 escalation 연락처와 분리 관리 |
| 인증 수단 | shared credential 금지, MFA 복구수단은 회사가 보유 |

계약 종료 시 받아야 할 것도 미리 적어 둡니다. 사건 파일 원본, 제출 영수증과 접수번호, correspondence history, 기한 일정표, export 포맷과 전달 기한까지 포함하는 편이 좋습니다. 종료 시점에 협의하면 늦습니다.

### handoff 품질과 정기 점검

대리인 운영은 사건이 생겼을 때가 아니라 평시 리듬에서 결정됩니다. 최소한의 RACI와 응답 기준만 있어도 품질이 달라집니다.

| 업무 | 내부 IP·법무 | 사업팀 | 외부 대리인 |
|---|---|---|---|
| 표장·권리자 구조 결정 | 결정 | 협의 | 참고 의견 |
| 출원 패킷 작성 | 작성 | 입력 제공 | 검토 |
| 제출 문안 확정 | 승인 | | 작성 |
| 기한 관리 | 이중 관리 | | 1차 관리 |
| 거절 대응 방향 | 결정 | 협의 | 옵션 제시 |
| 기록 보관 | 정본 보관 | | 사본 제공 |

기한은 대리인에게만 맡기지 않고 내부에서도 이중으로 관리하는 편이 안전합니다. 통지가 한 채널에만 오면 그 채널이 막혔을 때 복구가 어렵습니다.

분기마다 아래 정도만 남겨도 상태가 보입니다.

| 관할 | 상태 | 확인 사항 | 보완 기한 | Owner |
|---|---|---|---|---|
| 관할 A | 정상 | 기한·연락처 최신 | — | 내부 IP |
| 관할 B | 보완 | 송달주소 변경 미반영 | 다음 달 말 | 내부 IP |
| 관할 C | 공백 | 사건 기록 사본 미수령 | 이번 분기 | 법무 |

상태값은 `정상 / 보완 / 공백` 정도로 단순하게 고정하는 편이 좋습니다. 단순해야 보고가 빨라지고 우선순위도 쉽게 보입니다.

### 교체와 이관을 평시부터 설계한다

교체는 사이가 나빠져서만 생기지 않습니다. 담당자 이직, 조직 개편, 이해상충 발생, 관할 확대에 따른 재편성으로도 생깁니다. 그래서 교체 절차는 문제가 생긴 뒤가 아니라 계약 시점에 정해 두는 편이 낫습니다.

| 교체 트리거 | 먼저 확인할 것 |
|---|---|
| 응답 지연이 반복됨 | 기한 리스크가 있는 진행 건 목록 |
| 이해상충 발생 | waiver 가능 여부와 내부 승인 |
| 담당자 교체 | 인수인계 범위와 기록 상태 |
| 관할 재편성 | 관할별 자격 요건 재확인 |

이관에서 가장 위험한 것은 기한 공백입니다. 이관 패킷에는 진행 중 사건과 다음 기한, 제출 이력과 접수번호, 송달주소·연락처 변경 절차, 미결 질의를 함께 담고, **기한이 임박한 건이 없는 구간**을 골라 옮기는 편이 안전합니다. 송달주소나 대리인 기록 변경 자체가 관청 절차인 경우가 많으므로, 그 절차가 끝나는 시점까지를 이관 기간으로 잡습니다.

### 실행 시작점

한 번에 모든 관할을 정비할 필요는 없습니다. 요건이 갈리는 2~3개 관할만 먼저 정리하고 구조가 작동하는지 본 뒤 넓히는 편이 현실적입니다.

**이번 주**: 진행 중이거나 예정된 관할을 적고, 각각을 네 가지 유형 중 어디에 해당하는지 표시합니다. 유형이 불확실한 칸은 비워 두고 확인 대상으로 남깁니다.

**이번 분기**: 관할별로 현재 대리인, 송달주소, 공식 연락처, 다음 기한을 한 표에 모읍니다. 계정 소유권을 위 층 구분에 따라 정리하고, shared credential이 있으면 먼저 해소합니다.

**이후**: 브리프 질문지와 분기 점검표 형식을 고정하고, 교체·이관 패킷 목록을 계약 조항과 맞춰 둡니다.

내부적으로는 아래처럼 정기 업무로 돌리면 대리인 구조와 실제 운영이 벌어지지 않습니다.

| 관리 항목 | 권장 담당 | 주기 | 최소 산출물 |
| --- | --- | --- | --- |
| 기한·연락처 최신화 | 내부 IP | 분기 | 관할별 기한·연락처 표 |
| 대리인 인터페이스 점검 | 법무 | 반기 | 응답 기준 대비 실적 메모 |
| 이해상충 재확인 | 법무 | 연 1회 또는 사건 발생 시 | 확인 범위와 결과 기록 |
| 계정·권한 점검 | 내부 IP + 정보보안 | 반기 | 계정 소유권·접근 권한 목록 |
| 요건 변경 확인 | 내부 IP | 연 1회 | 관할별 요건 변경 여부 메모 |

대리인 선정의 목표는 가장 좋은 곳을 찾는 것이 아니라, 관할마다 다른 요건 위에서 우리 운영이 끊기지 않게 만드는 것입니다. 요건 구분이 먼저 서면 후보 비교는 그다음에 훨씬 단순해집니다.
