# Assignment, License, Quality Control 실무

미국 시장에서 owner와 actual user가 다를 가능성은 매우 높다. 따라서 권리이전과 라이선스는 단순 계약 이벤트가 아니라, register와 실제 사용 현장을 함께 맞추는 governance 문제로 봐야 한다.

## owner 변경과 권리이전

법인 재편, 투자, 사업양도, 지배구조 변경이 있을 때 assignment 기록을 제때 정리하지 않으면 이후 집행과 거래에서 설명 비용이 커진다. 특히 여러 국가에서 동시 구조조정이 일어나는 경우 미국 포트폴리오만 업데이트가 늦어지는 일이 흔하다. owner chain은 언제든 제3자가 읽어도 이해되게 관리해야 한다.

실무적으로는 거래가 끝난 뒤 한참 지나서 기록을 정리하기보다, 거래 구조를 검토할 때 미국 등록·출원 목록을 함께 점검하는 편이 좋다. 그래야 계약서의 권리귀속과 register의 표기가 분리되는 상황을 줄일 수 있다.

## owner-chain recordation workflow

assignment가 이루어진 뒤에는 register에 반영하는 recordation 절차를 완결해야 한다. 미국은 assignment/recordation 온라인 센터를 통해 제출하는 흐름이 일반적이며, 정확한 명칭과 제출 경로는 공식 출처로 재확인한다.

| 단계 | 할 일 | 책임자 | 완결 기준 |
|---|---|---|---|
| 1. 거래 동기화 | 미국 출원·등록 목록과 assignment 대상 일치 확인 | 법무/IP | 대상 리스트 |
| 2. 서류 준비 | assignment agreement, chain 문서, 관련 등록/출원 번호 정리 | 법무 | 제출 패키지 |
| 3. 온라인 제출 | assignment/recordation 온라인 센터 통해 제출 | 법무/IP | 제출 확인 증거 |
| 4. USPTO DB 모니터링 | register 상 owner 정보 반영 여부 주기적 확인 | IP | 반영 확인 |
| 5. 내부 보드 갱신 | 포트폴리오 보드와 register 일치 최종 점검 | IP | 동기화 완료 |

recordation은 제출 즉시 반영되지 않을 수 있으므로, 제출 확인만으로 끝내지 말고 USPTO DB 반영 결과를 모니터링하는 단계를 반드시 포함한다. register와 실제 owner가 불일치하면 유지 제출, 집행, 거래 모두에서 혼선이 생긴다.

## 라이선스와 품질통제

라이선스는 단순 사용 허락이 아니라 품질통제 체계를 포함해야 의미가 있다. 미국에서는 owner가 실제 사용 품질을 통제하지 못하면 상표 자산 자체가 약해질 수 있으므로, 승인 절차와 샘플 검토, 포장 가이드, 기록 보관 방식을 함께 운영해야 한다. 계약서 한 장보다 운영 흔적이 더 중요하다.

특히 해외 본사와 미국 판매 주체가 분리된 구조라면, 로고 사용 승인, 패키지 변경 승인, 채널별 표현 통제처럼 실제 운영에서 보이는 품질통제 흔적을 남겨 두는 것이 좋다.

## license QC adequacy checklist

QC 조항이 계약서에 들어 있다고 해서 문제가 해결되는 것은 아니다. 분쟁 시에는 조항보다 운영 기록을 먼저 요구하는 경우가 많다.

| 항목 | 계약서 수준 | 운영 기록 수준 |
|---|---|---|
| QC 조항 존재 | brand guideline, 승인 절차, 품질 기준 명시 | guideline 개정 이력 보관 |
| 승인 절차 | 승인 주체와 시한 정의 | 승인 이메일·회의록·샘플 검수 기록 보관 |
| 샘플 검토 | 검토 기준과 반려 권한 명시 | 검수 기록·반려·승인 샘플 아카이브 |
| 포장/표현 통제 | 채널별 표현 규칙 정의 | 실제 포장·광고 자료와 guideline 일치 기록 |
| 위반 시 조치 | 계약상 보정/해지 조건 | 위반 발견·시정 요구·후속 조치 기록 |

라이선스 QC는 "조항이 있느냐"를 넘어 "활동을 아카이빙했느냐"가 핵심이다. owner가 실제로 품질을 통제하고 있음을 입증할 수 있어야 상표권이 흔들리지 않는다.

## 거래 구조 체크리스트

현재 누가 owner인지, 누가 실제로 판매하는지, 어떤 계약이 활성 상태인지, marketplace와 invoice에는 누구 이름이 나가는지를 점검한다. 이 정보가 정리되지 않으면 specimen 설명, 유지 제출, 분쟁 대응 모두에서 동일한 혼선이 반복된다.

운영상으로는 owner 변경, 신규 라이선스 체결, 유통 구조 변경 같은 이벤트가 생길 때마다 동일한 체크리스트를 반복하는 편이 안전하다. 상표 거래 구조는 한 번 정리해 두고 끝나는 것이 아니라, 사업 구조가 바뀔 때마다 다시 맞춰야 하는 항목이다.

## assignment/license QC 매트릭스

거래 구조 문서는 계약서보다 QC 매트릭스로 보는 편이 운영에 더 도움이 된다.

| 이벤트 | 꼭 확인할 것 | 누가 잠글지 |
| --- | --- | --- |
| assignment | owner chain, recordal timing, related marks 범위 | 법무/IP |
| 신규 licence | quality control, 승인 절차, evidence owner | 법무 + 브랜드팀 |
| distributor 변경 | invoice 표기, marketplace seller, packaging control | 사업팀 |

## 문서 갱신 트리거

아래 이벤트가 생기면 상표 거래 구조도 같이 점검하는 습관이 필요하다. 기존 이벤트-매트릭스를 문서 갱신 트리거 표로 확장하면, 어떤 사건이 발생했을 때 어떤 register/QC 문서를 열어 봐야 하는지 빠르게 찾을 수 있다.

| trigger | 같이 열어 볼 문서 | 갱신 우선순위 |
| --- | --- | --- |
| 법인 재편 | assignment memo, register update list | 높음: owner chain 불일치 시 집행/거래 장애 |
| 신규 라이선스 체결 | QC checklist, brand guideline | 높음: QC 미비 시 권리 흔들림 |
| 채널 확대 | specimen/evidence plan, marketplace naming memo | 중간: 사용 주체와 evidence owner 일치 |
| 지배구조 변경 | assignment/recordation 상태, license ledger | 높음: register-실제 권리 불일치 |
| 브랜드 리뉴얼 | brand guideline, QC 승인 기록 | 중간: 새 표장 버전의 QC 통제 |
